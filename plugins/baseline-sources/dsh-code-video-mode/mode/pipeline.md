# 生产流水线：八阶段与产物

主线：受理 → 策划冻结 → 技术与脚手架 → 素材与音频 → 逐场景实现 → 汇聚导出 → 验证修正 → 交付。
进入任一阶段前，确认上一阶段的产物已经落盘；不带着未冻结的方案往下走。可复用的策略见 `playbooks/`，模板见 `templates/`。

## 阶段 1：受理与决策
产物：`spec/brief.md`
- 一句话目标（给谁看、看完要记住什么）、时长、画幅、分辨率、帧率、语言、配音有无、字幕有无。
- 缺省值与理由逐条记录；需要向用户确认的决定性信息集中成一次提问。
- 结束条件：全部参数有值，无待定项。

## 阶段 2：策划与冻结
产物：`spec/script.md`、`spec/storyboard.md`、`spec/storyboard.yml`、`spec/timeline.csv`、`spec/animation-guide.md`、`spec/visual-spec.json`、`spec/scene-breakdown.yml`
- 文案：口播稿与屏幕文字分开写；屏幕文字只保留关键词与数字，不写整段话；前三秒给出钩子。
- 分镜：每个镜头写清"画面主体、运动、文字、音频点、转场出法"。`storyboard.md` 给人看，`storyboard.yml` 给机器读，二者内容必须一致。
- 时间线：`timeline.csv` 每行一个镜头，列为 `id,scene,start_frame,end_frame,frames,duration_s,beat,audio_cue,transition_out`；累计帧数必须等于总帧数。
- 动画指南：逐镜头给出入场/驻留/出场三种状态的关键值、缓动曲线名与参数、相机运动轨迹、以及禁止做的事（例如"本镜头不做缩放"）。
- 视觉规范：调色板（含初始值与用途）、字体（含实际字体文件路径）、栅格与安全区、层级与景深范围、效果预算（每镜头的模糊/发光/粒子上限）。
- 场景拆分：场景边界、每场景负责的镜头、共享工具与资源、依赖顺序、可否并行。
- 冻结检查：四份规范自洽（时长/帧数/镜头 id 一致）、颜色与字体可用、每场景都有明确的并行判定。

## 阶段 3：技术方案与脚手架
产物：`spec/tech-plan.md`、可运行的工程骨架、一张验证渲染链路的测试帧
- 调用一次 `video_render_capabilities`，据实选择渲染与编码路径，写入 `tech-plan.md`（含渲染预算：预计帧数、单帧目标耗时、总上限、降级顺序）。
- 搭工程：入口、`fps`/`width`/`height`/`durationInFrames` 常量、共享样式与时间轴工具、确定性帧驱动约定。
- 冒烟：渲染一张测试帧（含文字、图形、一层效果）并目视确认；链路不通先解决链路，不进入内容制作。

## 阶段 4：素材与音频
产物：`public/` 下的字体与音频、`spec/audio-map.csv`
- 画面素材：优先生成（SVG/Canvas/着色器/代码排版）；外部素材必须有明确授权来源，不下载未知来源资源。
- 配音：按 `script.md` 逐句生成，保留每句音频的起止时间；文件命名与句子 id 对齐。
- 字幕：与配音逐句对应，切分为可读长度，写入 `public/` 或直接进入实现。
- 声床：BGM 选定并定好入出点；SFX 按镜头卡点列表（Whoosh=转场、Impact=重音、Riser=铺垫、Click/Tick=计数与小动作）。
- 量测：为每句配音取实际时长，写进 `spec/audio-map.csv`，并据此校准 `timeline.csv`；量测方法见 `mode/audio-and-sync.md`。

## 阶段 5：逐场景实现
产物：`scenes/Sxx/` 实现与逐场景预览
- 顺序：默认按时间线顺序推进，先做最能暴露技术风险的那个场景。
- 每个场景完成即渲染预览帧序列并检查：运动连续、文字不溢出安全区、效果在预算内。
- 并行前提：规范已冻结且场景拆分已标注可并行；并行时每个子代理只写自己的目录，主 Agent 保留公共工具。
- 结束条件：每个场景都能独立预览通过，且与 `storyboard.yml` 一致。

## 阶段 6：汇聚与导出
产物：`out/<name>.mp4` 与导出命令记录
- 合成：按时间线拼接场景，处理场景衔接处的连续运动，禁止直接硬切导致节奏断裂。
- 音频：一次性混流（配音 + BGM + SFX），混音参数与目标响度写进导出脚本注释。
- 编码：H.264 + AAC、`yuv420p`、`+faststart`；输出文件名含分辨率与时长。
- 断点续跑：帧序列与音频中间产物保留在 `out/`，允许从失败点续渲。
- 结束条件：成片文件存在且 `ffprobe` 读数符合规格。

## 阶段 7：验证与修正
产物：`out/qc-report.md` 与抽帧证据 `frames/`
- 逐项执行 `verification/qc-checklist.md`；每项写"结论 + 证据"（命令输出摘要、帧文件名、目视判断）。
- 缺陷修正后复验该项与耦合项；修正不动摇已通过的项。
- 结束条件：清单无失败项，或失败项已按契约第 6 节止损并如实记录。

## 阶段 8：交付
产物：成片、源码、关键帧、`README.md`
- 用 `present` 展示成片；关键帧作为附证。
- 交付说明四段式：做了什么 / 怎么做的 / 验证了什么 / 未验证或自行取定的部分。
- 交付前删除本次制作目录内可再生成的临时文件，只保留成片、源码、关键帧与说明。
