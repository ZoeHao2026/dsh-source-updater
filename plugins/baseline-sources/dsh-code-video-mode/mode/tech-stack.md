# 技术栈、确定性与降级

## 1. 选择矩阵
| 需求 | 首选 | 次选 | 说明 |
| --- | --- | --- | --- |
| 解说、数据动画、文字驱动 | Remotion | Motion Canvas | React 生态与帧时间线成熟，`spring()`/`interpolate` 直接表达缓动 |
| 图表、流程图、数学式运动 | Motion Canvas | Remotion | 生成器语法对"按步骤出现的图形结构"最省代码 |
| 生成式画面、粒子、流场 | p5.js / Canvas 2D | 着色器 | 代码短、迭代快，适合抽象与背景层 |
| 3D / 2.5D 空间、景深、辉光 | Three.js + WebGL/GLSL | CSS 3D | 真实机位运动与后处理需要 3D 管线 |
| 精确矢量、遮罩、形变、动态字体 | SVG + CSS/TS | Canvas | 排版与描边精度最好 |
| 需要完全控制的逐帧 | Playwright + Chromium | 框架自带渲染器 | 固定时间步长、逐帧截图、离线可行 |
| 编码、混流、滤镜、量测 | FFmpeg / ffprobe | 框架自带编码 | 一切"事实核对"的最终依据 |

选择原则：能用代码生成就不用外部素材；能在一层里表达就不叠三层；先选一个主栈跑通，再按镜头局部引入第二栈（仍须在 `tech-plan.md` 记录）。

## 2. 确定性渲染（强制）
- 时间只来自帧号：`t = frame / fps`。禁止用 `Date.now()`、真实计时器或 `requestAnimationFrame` 推进动画。
- 逐帧渲染按帧号定位并等待画面稳定（字体加载、图片解码、首帧着色器编译完成）后再截图。
- 随机数固定种子；种子写进 `visual-spec.json`，保证同参数重跑画面一致。
- 字体必须显式加载并等待就绪；中文字体尤其要确认字重与字形文件真实存在，避免回退字体导致排版漂移。
- 抗锯齿与像素格式固定（例如 `pixelRatio` 固定为 1 或 2 并在规范里写明），避免不同帧清晰度不一致。
- 渲染日志保留每帧耗时，便于定位慢帧（慢帧会造成观感卡顿，必须与真实静帧区分）。

## 3. 渲染预算模型
开工前填 `tech-plan.md`：
- 总帧数 = 时长 × fps（取整）。例：30 秒 × 30fps = 900 帧。
- 单帧目标耗时：简单矢量层 30–120ms；含模糊/发光后处理 150–400ms；含 3D 与体积效果 400ms–1s。按此估算总渲染时长并写入方案。
- 降级顺序（固定）：降低后处理层数 → 降低分辨率（1080p→720p）→ 减少粒子/光线步进迭代 → 缩短时长。任何降级都要在交付说明中写明。
- 单帧超过目标 3 倍即视为超预算，先优化再考虑降级，不靠拉长总时间硬扛。

## 4. 本机能力与降级路径
先调用 `video_render_capabilities` 得到真实情况，再按下列顺序处理：
- **有 Chrome/Edge 无 Playwright**：用系统浏览器做无头逐帧/快速预览，或只做本地预览，把完整渲染交给框架自带渲染器。
- **无 ffmpeg**：把 `ffmpeg-static` 作为工程本地依赖（离线安装需用户提供包或缓存），或使用框架自带的编码/合成能力；两者都不可用时，输出帧序列 + 预览 MP4 的替代方案，并在交付说明中明确降级内容（例如缺少 faststart、需要用户自行编码）。
- **无网络**：不下载字体、素材、音色；改用本机已装字体、程序生成图形、本地 TTS。方案文件里记录"离线完成"这一前提。
- **无 edge-tts**：优先使用用户提供的音频；否则只做无声版 + 完整字幕，并说明配音缺失。
- **内存/显存受限**：分段渲染再拼接（每段独立进程），避免一次性把全部帧留在内存。

## 5. 工程结构约定
```
code-video-<slug>-<yyyymmdd>/
├── spec/          方案与规范（唯一事实源）
├── src/           实现：入口、共享样式、时间轴工具、场景装配
├── scenes/Sxx/    逐场景（并行时每个子代理只写自己目录）
├── public/        字体、音频、贴图（离线可用）
├── out/           帧序列、中间音频、成片、qc-report.md
└── frames/        抽帧证据图片
```
- 入口文件只做参数与场景装配；动画值都从可复用的缓动/时间工具取，禁止在场景里散落魔法数字。
- 共享样式集中管理：颜色、间距、字号、阴影、模糊半径都以令牌形式给出，场景只引用令牌。
- 导出脚本固定一条命令，参数（帧率、分辨率、输出名）从常量读取，保证复现。

## 6. 复用与升级
- 同一主题系列复用上一部作品的 `visual-spec.json` 与共享样式，保持品牌一致性；但每次都要重新核对时长与帧数。
- 框架版本升级后，先用测试帧复验渲染链路，再开始新制作；不把旧工程的渲染假设直接套到新版本。
