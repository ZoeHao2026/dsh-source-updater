# 跨任务执行契约

适用：每次制作都遵守。本文件只定义不变量与判据；具体阶段的产物见 `mode/pipeline.md`，视觉与音频规则见 `mode/visual-language.md`、`mode/audio-and-sync.md`，验收门禁见 `verification/qc-checklist.md`。

## 1. 授权与自主边界
- 用户的主题描述即制作授权，覆盖"选题、文案、分镜、视觉、音频、技术栈"的全部决定，不需要逐项确认。
- 需要额外授权的只有三类：涉及真实品牌/商标的对外发布、使用用户未提供的真实数据、产生额外费用或对外上传素材。除此之外自主推进。
- 不确定时选择可逆方案并记录理由；不要把"多问一句"当作规避判断的手段。

## 2. 单一事实源
- 制作期间，`storyboard.yml`、`visual-spec.json`、`animation-guide.md`、`timeline.csv` 是唯一事实源；`timeline.csv` 的累计时间必须与总时长、音频长度一致。
- 方案冻结后只允许向前修订：先改方案文件，再改实现，并记录修订原因与影响范围。
- 任何"临时改一下"的偏离都必须回写方案文件；禁止让多份不一致的描述同时存在（例如分镜表与时间线冲突）。

## 3. 规范冻结先于并行与实现
- 冻结条件：四份规范文件齐备、时长与帧数自洽、每场景有明确镜头与起止时间、共享样式工具与视觉令牌已定义、调色板与字体文件已锁定为实际存在的路径。
- 只有冻结后才允许：开始写生产代码、派发子代理、启动长渲染。
- 子代理只写自己的 `scenes/Sxx/`；共享规范、公共样式、合成入口、声床与导出脚本只由主 Agent 写。

## 4. 确定的渲染
- 帧号驱动一切：动画、着色器时间、粒子、镜头运动都取 `frame / fps` 计算，不使用真实时钟或 `requestAnimationFrame` 推进。
- 随机必须带种子且种子写入方案文件；同一次渲染重复执行应得到一致的画面。
- 单帧渲染检查通过后，才允许启动整段渲染；整段渲染必须可断点续跑。
- 时长以帧数定义（`总帧数 = 时长 × fps`，取整），不以浮点秒数定义。

## 5. 证据式验证
- "已完成"的证据只能是：成片文件存在、`ffprobe` 读数符合规格、关键帧目视核对通过、QC 清单逐项有证据。
- 命令退出码为 0、日志无报错、模型自述，都不构成完成证据。
- 每次修正后必须复验受影响的项目，并复验与它有耦合的项目（例如改了配色要复看对比度与字幕可读性）。
- 未验证的范围必须写在交付说明里；不隐瞒、不含糊。

## 6. 预算与止损
- 开工前在 `tech-plan.md` 写明渲染预算：预计帧数、单帧渲染目标耗时、总渲染时间上限、可接受的降级顺序（分辨率 → 时长 → 效果强度）。
- 单帧渲染超过目标的 3 倍时先优化（减少滤镜层、降低粒子数、简化着色器），再考虑降低分辨率；不得靠延长总时长硬扛。
- 修正循环有上限：同一缺陷连续三次修正无效时，改为记录该缺陷并提供可用的降级版本，继续推进其余部分。

## 7. 资源与输出规范
- 每个制作使用独立工程目录，命名 `code-video-<slug>-<yyyymmdd>`；所有产物在该目录内，不污染用户其他目录。
- 目录约定：`spec/`（方案文件）、`src/`（实现）、`public/`（字体、音频、贴图）、`scenes/Sxx/`（逐场景）、`out/`（渲染与成片）、`frames/`（抽帧证据）。
- 大文件（帧序列、临时音频）放 `out/` 与 `frames/`，交付只保留成片、源码、关键帧与说明。
- 清理只删除本次制作目录内的临时文件；不删用户既有文件。

## 8. 诚实交付
- 交付说明固定包含四段：做了什么（创意与结构）、怎么做的（技术栈与参数）、验证了什么（证据）、没有验证或自行取定的部分。
- 成片不达标就如实降级说明（例如"因缺 ffmpeg 仅输出帧序列与预览"），而不是用模糊措辞掩盖。
